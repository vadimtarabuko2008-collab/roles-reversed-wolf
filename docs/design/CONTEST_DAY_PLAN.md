## Как тема проявляется в игре

Игрок управляет привычным хищником, но его успешная тактика — вести себя как безобидная овца. Днём он выбирает момент для добычи и прячется в стаде. Ночью роли охотника и добычи разворачиваются: охрана становится активнее, волку необходимо скрываться; при наличии соперника он дополнительно защищает овец, которых сам хотел забрать.

Смена ролей должна менять поведение, а не только цвет света. Минимальное различие: днём собака патрулирует и реагирует на разоблачение, ночью активнее проверяет стадо и ищет волка. На границе ночи даём краткую подсказку о смене роли. Более сложный охотник и конкуренция усиливают идею, но ядро темы не зависит от их готовности.

Предложенный короткий баланс: 8 овец, одна сложность, цикл 120 секунд (50 день + 10 сумерки + 50 ночь + 10 рассвет), квота 4 овцы за полный цикл, задержка после успешного получения добычи 12 секунд, надевание костюма 3 секунды. Минимум два цикла для идеального исхода; целевая длина попытки 3–5 минут проверяется игрой. Это новый конкурсный профиль, а не незаметная замена полного профиля 18 овец / 160 секунд / 25 секунд из 01.

## Объём по приоритетам

### Обязательная основа

Одна карта, фиксированная камера, один игрок, небольшое стадо, одна собака, две формы игрока, трёхсекундное надевание, простое подозрение, потеря видимости за укрытием, получение добычи, понятная цель, проигрыш, победа и перезапуск. Смена дня и ночи влияет на угрозу. Интерфейс показывает оставшихся овец, состояние игрока и доступность действия. Короткое обучение, несколько согласованных звуков, кнопка отключения звука.

Система здоровья сразу хранит обычный урон и постоянное уменьшение максимума отдельно. Если используется первоначальное правило еды, она лечит только обычные раны. Если вводится соперник, успешно унесённая овца не возвращается и идеальный исход становится недоступен. Эти подтверждённые решения не упрощаются в противоположные правила.

### Расширение при успешной контрольной точке

Один соперник ночью: выбирает овцу, уносит к выходу, освобождает её при перехвате. Один простой приём игрока без серии комбо. Упрощённый локальный след с конечным временем жизни, два уровня повреждения костюма, пастух с читаемым предупреждением. Каждое расширение принимается отдельно после работающего завершения забега.

### После конкурса

Несколько сложностей, большие волны волков, схватки соперников друг с другом, сложное перехватывание траектории собакой, физика ткани, ремонт костюма, большая карта, полная система ветра, тысячи кадров, 3D-скелеты с нуля, мобильное управление и дополнительный контент. Количество недоделанных систем не повышает конкурсную завершённость.

### Автору до начала программирования

1. Проверить вход в GitHub и itch.io, доступ к зарегистрированной команде и отправке работы. Пароли, коды подтверждения и токены вводить самостоятельно в интерфейсах сервисов.

3. Открыть ту же папку, которая будет рабочей в Codex. Предлагаемый код проекта — подпапка `game` текущего рабочего репозитория. Документация и принятые исходники лежат рядом в этом же репозитории. До старта проверить, что здесь нет другой игры или полезной существующей истории. Второй вложенный .git не создавать.
4. Подготовить название игры/репозитория и публичное имя автора коммитов; адрес можно взять из GitHub noreply. Не требуется раскрывать личную почту.

6. При желании работать именно внутри редактора можно установить официальное расширение Codex и войти своим аккаунтом. При работе в уже открытом приложении Codex это необязательный шаг; не тратить на него утренний блок.
7. Выбрать условия публикации собственных материалов и кода. Я подготовлю подходящий LICENSE после выбора, а лицензии сторонних файлов запишу отдельно. Публичный репозиторий не разрешает автоматически перепубликовывать любой скачанный ассет.

Node, npm и Git повторно устанавливать не нужно. Three.js, Vite и необходимые зависимости я добавлю в проект и зафиксирую версии при реализации. Unity, Unreal, Docker, сервер, база данных и платный API для поведения персонажей не нужны для выбранного объёма.

### Git в течение дня

Я подготавливаю изменения, выполняю проверки, описываю результат и формирую осмысленный коммит. Отправка на GitHub выполняется через настроенный Git; если авторизация доступна только в VS Code, автор нажимает Push/Sync и проверяет результат на сайте. Авторизацию можно настроить один раз утром. Подготовка плана сейчас не создаёт публичный репозиторий и не публикует материалы автоматически.

На каждом этапе: проверить список файлов → проверить игру → сохранить законченное изменение коммитом → отправить → убедиться, что коммит появился на сайте. Достаточны осмысленные коммиты после небольших готовых изменений; число коммитов не является конкурсной нормой. Ориентир 8–12 за день полезен как рабочий ритм, но не как квота для имитации активности.

Примеры будущих сообщений, использовать только по факту: «Добавлен запускаемый веб-проект», «Добавлены карта и столкновения», «Добавлены маскировка и добыча», «Добавлены погоня и завершение забега», «Добавлен ночной соперник», «Подключены принятые материалы», «Исправлены ошибки повторного запуска», «Подготовлена конкурсная сборка и отчёт».

В коммит не попадут node_modules, кэши, ключи и личные файлы. Собственные исходники и лицензированные материалы, предусмотренные регламентом, не теряются из-за исключения временных файлов. Для крупного исходника заранее проверить способ хранения и доступность скачивания, не откладывать первую отправку модели до вечера.
